## 1. Project at a glance

GlassHome is a local, Chromium-based browser extension that replaces the New Tab
page with a customizable glass-style dashboard. The README names Chrome, Edge,
and Brave. The implementation is plain HTML, CSS, and JavaScript; no framework
or bundled third-party JavaScript/CSS package is declared.

The extension is configured as Manifest V3. Its main page is newtab.html, its
interface logic is app.js, its visual styles are in styles.css, and its service
worker is reminders-background.js.

The UI and documentation are primarily Vietnamese, with some English labels and
copy. Preserve the existing bilingual style unless a task asks to change it.

## 3. Features visible in the current source

- Live clock, localized date, greeting, optional display name, 12/24-hour
  display, configurable clock style/color/font/scale/spacing.
- Day progress bar with percentage, quarter-hour reminder text, adjustable
  color/font, and optional operating-system notification permission.
- Weather widget using Open-Meteo geocoding and current-weather endpoints.
- Quick notes, automatically saved locally after a short debounce.
- “Joy” mini-widget with a configurable emoji, animated particles, counter, and
  reset action.
- Hydration tracker: daily total and goal, history by local date, preset/custom
  drink amounts, undo, reminder interval and hours, pause/resume, snooze, and
  optional background notifications.
- Search submits to Google and requests Google search suggestions for queries of
  two or more characters.
- Customizable shortcut dock with built-in defaults, add/edit/delete, automatic
  favicon, remote icon URL, uploaded icon, or text/emoji fallback.
- Bookmarks view combines browser bookmarks (when the browser API is available)
  with user-created local bookmarks and filtering.
- Widget visibility controls, light/dark/system themes, wallpaper upload or URL,
  blur/dim/glass controls, free-position layout, and many widget dimensions,
  offsets, radii, and other visual settings.
- Dynamic Bar text/appearance, signature/footer customization, and support-site
  link settings.

## 5. Runtime and data flow

The page uses the browser's chrome.storage.local through a small `store` wrapper
in app.js. If the Chrome extension API is not present, that wrapper falls back to
localStorage, which is useful for a basic page preview. Browser-only features
such as extension notifications and native bookmarks require the extension
context and the corresponding browser APIs.

Settings, notes, custom links/bookmarks, wallpaper data, layout, and hydration
history are persisted locally by the browser. Uploaded wallpaper data is read
as a data URL and stored locally; the UI limits it to 5 MB. Uploaded dock icons
are limited to 1 MB. Do not promise that settings automatically sync between
devices; no sync-storage implementation was found.

Important storage keys observed in app.js and reminders-background.js:

- Dashboard: links, notes, wallpaper, theme, city, visibleWidgets, displayName,
  hour12, islandAlways, islandText, joyCount, joyEmoji, customBookmarks.
- Visual settings: wallblur, dim, glassStrength, clockGap, clockStyle,
  clockColor, clockFontFamily, clockFontScale, clockTopOffset,
  clockLeftOffset, dayTrackerTopOffset, dayTrackerFontSize, dayProgressColor,
  widgetRightOffset, widgetGap, weatherRadius, notesRadius, joyRadius,
  notesHeight, dockRadius, functionMenuSize, functionMenuUnframed,
  hydrationWidgetWidth, hydrationWidgetHeight, hydrationCollapsedWidth,
  hydrationCollapsedHeight, hydrationCollapsedDropWidth, and
  hydrationCollapsedDropHeight.
- Layout: freeLayout and layoutVersion. restoreLayout() uses layout version 41;
  when it sees another version, it removes the saved freeLayout coordinates and
  writes version 41. Be careful when changing this migration behavior.
- Hydration: hydrationData. This object includes settings, historyByDate,
  nextReminderAt, lastReminderAt, lastHomeReminderAt, and snoozedUntil.
- Background day reminders: glassboardReminderNotificationState.

The exact set of persisted visual settings may evolve. Search app.js for
`store.get`, `store.set`, and `store.remove` before renaming a key; changing
storage names can break existing users' saved preferences.

## 6. Reminders and notification behavior

Day progress is calculated from local clock time in app.js and refreshed every
second. The on-page reminder text is selected from reminders-data.js by the
current 15-minute time slot.

reminders-background.js separately uses chrome.alarms for quarter-hour
notifications. Notifications are optional: manifest.json declares
`notifications` under optional_permissions. The UI requests it after a user
action. The background script checks permission before sending notifications.

The hydration defaults in hydration-core.js are:

- Reminders enabled.
- 60-minute interval (custom interval is clamped to 5–480 minutes).
- Allowed hours 07:00–22:30.
- Daily goal 2,000 ml.
- Background notifications disabled until explicitly enabled.

Hydration totals are stored by local calendar date. The time helper supports
allowed periods that cross midnight. Browser notification actions include
“Snooze 10 minutes” and “Drank 200 ml”. A page alert is also used while the
dashboard is open.

See “Các lỗi đã sửa được xác minh” below for the confirmed reminder fixes and
their commit references. Do not remove those safeguards without reproducing
the original issue and adding an appropriate regression test.

## 7. Permissions and external network requests

Required permissions in manifest.json:

- storage — Local extension data.
- bookmarks — Read the browser's bookmarks for the bookmark panel.
- alarms — Schedule background reminders.

Optional permission:

- notifications — System notifications, requested by the UI when appropriate.

Declared host permissions include Open-Meteo geocoding/forecast, Google search,
Google suggestions, Google favicon service, and DuckDuckGo icons. Source code
uses Open-Meteo for weather, Google for search/suggestions/favicons, and accepts
user-supplied wallpaper/icon/shortcut URLs. THIRD_PARTY_NOTICES.md currently
records DuckDuckGo icons as declared but unused.

Search queries are sent to Google when submitted or when suggestions are
requested. City names/coordinates are sent to Open-Meteo when weather is loaded.
Automatic favicons and user-supplied remote images require network access.
Offline UI features and uploaded/local images do not require these services.
Use THIRD_PARTY_NOTICES.md for the repository's more detailed third-party notes.

1. Open `chrome://extensions` in Chrome or `edge://extensions` in Edge.
2. Enable Developer mode.
3. Choose “Load unpacked” and select the project root (the folder containing
   manifest.json).
4. Open a new tab. After source changes, use Reload on the extension page and
   open a fresh tab. Inspect the extension/service-worker errors if behavior
   does not update.

   hydration-core.js and reminders-background.js before changing behavior.

4. Test the exact feature in Chrome/Edge. Check both the visible page and
   service-worker behavior for alarms/notifications.

### Lịch nhắc bị gửi lặp hoặc dồn thông báo

- Commit 1565e63 (2026-11-15) addresses repeated/stacked reminders. It added a
  helper that identifies the current 15-minute reminder slot and only sends an
  alarm's message when that alarm matches the current slot. This avoids
  treating every alarm callback as the currently due reminder.
- Commit 3b17bbc (2026-11-16) clears existing `glassboard-reminder-*` alarms
  before rebuilding the schedule. This prevents old alarms from accumulating
  across a reschedule/restart.
- The same commit checks both the alarm's scheduled calendar date and the
  current reminder slot before sending. This guards against a stale alarm from
  a previous day firing as if it were today's reminder.
- The current implementation also records sent reminder times by local date
  in `glassboardReminderNotificationState` and serializes notification work
  through a queue. Preserve these safeguards when modifying notification
  scheduling.

   bắt đầu bổ sung từ mục `##12`.

## 15. Quy tắc bàn giao cho AI tiếp theo

- Đọc handoff này cùng README, manifest và đúng các source file trong thư mục
  được chọn trước khi sửa. Handoff là ghi chú hỗ trợ, không thay thế source hay
  lịch sử Git.
- Không tự suy diễn rằng yêu cầu UI đồng nghĩa với quyền xóa dữ liệu hoặc reset
  cài đặt người dùng. Mặc định: giá trị mới chỉ áp dụng khi key chưa tồn tại.
- Người dùng từng yêu cầu hỏi trước khi sửa trong một lần debug thông báo.
  Nếu một yêu cầu mới lại yêu cầu “hỏi trước”, hãy xác định nguyên nhân/ảnh
  hưởng trước và xin xác nhận trước khi thay đổi; không tự thực hiện sửa chữa.
- Giữ UI tiếng Việt và phong cách hiện có; hạn chế thay đổi ngoài phạm vi.
  Kiểm tra HTML/JS/CSS cùng các storage key liên quan và kiểm thử đúng hành vi
  thực tế trên browser.
- Sau khi cập nhật guide, không tuyên bố các thay đổi local đã được commit,
  phát hành, hay đồng bộ giữa hai thư mục nếu chưa xác minh Git và file đích.
